# WiseDepot Client Bridge 与双端 UI 重构设计

## 目标

在不扩张业务范围的前提下，整理 `WiseDepotClient` 的 Bridge，删除经引用分析与测试证明的废弃代码，并把现有 24 个业务屏与 1 个登录屏重构为适合电脑和手机的双端界面。

本设计只针对当前 Client。所有 UI 必须有以下至少一种真实依据：

1. 当前已经注册的业务屏；
2. 当前页面已经调用的 Bridge 方法；
3. 当前后端实际返回的字段；
4. 已生成契约中存在、并经过后端行为验证后才允许接线的方法。

视觉样稿仅定义布局、层级、色彩和交互方式，不自动增加样稿中的业务能力。

## 决策

保留“单份 React Web UI + 电脑/手机双 Shell + 单份 Kotlin Bridge”的总体架构，不拆成两套前端，也不把手机业务页改写为原生界面。

重构分为五个可独立验收的阶段：

1. Bridge 正确性、安全边界与高置信度废弃代码清理；
2. 共享导航、响应式基础组件与无障碍修正；
3. 电脑端列表、详情和表单桌面化；
4. 手机端任务流、扫码和底部动作区重构；
5. 发布门禁、真机和崩溃恢复验证。

Bridge 与 UI 分阶段落地，但使用同一套自动化门禁，避免同时大改后无法定位回归。

## 硬约束

- 不增加没有现有数据链路支撑的趋势图、同比环比、热力图、3D 仓库、设备遥控、轨迹地图、实时视频、环境传感器或库存直接改数。
- 契约存在但当前页面尚未接线的功能属于二期候选，不能借本次视觉重构直接上线。
- 不更改协议版本、帧字段、错误码、会话事件、凭据文件格式及生产契约数量，除非有独立迁移设计。
- 不删除备用 Plain WebSocket transport、WSA 回退、自检、现场诊断脚本或明确保留的未来事件端口。
- 删除代码前必须先有静态门禁或行为测试证明；不能只凭名称、覆盖率或单次搜索结果判断。
- 电脑和手机共用业务组件与数据逻辑，Shell 只负责布局、导航与宿主能力呈现。
- 所有主要触控目标至少 48px；键盘操作、焦点恢复、错误播报与系统减少动效必须可用。

## 当前真实功能范围

### 登录与概览

- 登录：验证码生成、刷新和账号密码登录。
- 看板：四个真实 KPI、当前任务、未处理告警。
- 告警：列表、详情、日志、确认、状态处理和忽略原因。

### 库存

- 库存：列表、搜索入口、详情、锁定和解锁。
- 商品：列表、新建、删除。
- 仓库：列表、新建、删除。
- 标签：列表、详情、按编码查询、批量绑定和批量解绑。
- 出入库单：列表、新建、详情、提交、撤回和审核。

### 现场

- 设备：统计、列表、按编码查询和详情。
- 巡检任务：分页列表、详情、差异、开始、保存进度、结束和新建。
- 巡检结果：列表、详情、确认和录入。
- 手动补录：多行 NFC、可选 TID/备注、连续扫码和提交。

### 我的

- 消息：列表、未读数、详情、标记已读、全部已读和清空。
- 用户：列表、新建、详情、角色只读、重置密码和验证码删除。
- 个人资料：读取、更新、偏好设置和修改密码。

### 二期候选

以下能力虽然存在于生成契约，但本次不直接接 UI。接线前必须验证响应结构、权限、错误语义和业务规则：

- 商品和仓库编辑；
- 单标签绑定、解绑和编辑；
- 单据更新及明细增删；
- 巡检计划 CRUD 和 PDF；
- 用户编辑及角色授予、清除；
- 头像上传和删除；
- 报表创建、执行和导出；
- 设备创建、编辑、删除和配置；
- 库存统计、告警统计和退出登录。

退出登录虽列为二期接线项，但会话入口必须在本次 UI 中预留明确位置；若后端行为验证通过，可在同阶段启用。

## UI 信息架构

### 共享导航状态

新增单一的 Shell 导航状态所有者，保存：

- 当前一级域；
- 当前列表页；
- 详情栈及参数；
- 每页筛选、页码、滚动位置；
- 返回目标；
- 当前扫码接收者。

`AppFrame` 只切换布局，不再因跨过 600px 断点而销毁业务状态。桌面和手机通过同一导航模型渲染不同布局，并逐步同步到 URL/history，使刷新和返回键可恢复。

### 电脑端

- 固定侧栏只显示四个一级域和真实页面；新建、录入等动作移到页面上下文，不与浏览页并列堆满导航。
- 列表类页面使用语义表格、筛选栏、分页和右侧详情；有批量能力的页面显示持久批量工具栏。
- 详情类页面使用概要、明细和动作区分栏；不把手机卡片简单放大。
- 表单类页面使用两栏分组和提交摘要；危险动作与普通保存明确分离。
- Bridge 状态保留为低干扰状态，不显示虚构延迟，除非真实测量链路存在。

### 手机端

- 底栏保留概览、库存、现场、我的四个一级域。
- 域内页面使用明确列表或菜单，不依赖隐藏滚动条的横向导航。
- 列表使用卡片，详情独立入栈；表单保持单任务流程。
- 扫码只在相机能力存在时展示；当前输入框或业务屏优先消费扫码，Shell 只在无人消费时跳标签详情。
- 页面动作由 Shell 感知的动作槽承载，位于底部导航之上，并避开安全区和输入法。

## 逐页布局规则

### 列表与主从页

应用于告警、库存、商品、仓库、标签、出入库单、设备、巡检任务、巡检结果、消息和用户：

- 电脑：`ResponsiveDataView` 渲染表格，选中行在 `MasterDetailWorkspace` 中打开详情。
- 手机：同一数据模型渲染业务卡片，点击后进入详情栈。
- 当前仅筛选已加载 20 条数据的搜索框必须标注“筛选本页”；只有已连接服务端搜索的方法才能标注为全局搜索。
- loading、empty、error、success 四态不改变业务含义。

### 详情与流程页

应用于告警详情、库存详情、标签详情、单据详情、设备详情、巡检任务详情和消息详情：

- 电脑：概要与明细并列，动作位于内容列内部 sticky 区。
- 手机：纵向信息组，主动作位于底部动作槽。
- 仅展示 DTO 真实字段；设备速度和轮参数保持只读，不使用滑块暗示可调。
- 库存详情不提供直接改库存数入口。

### 表单与批量页

应用于新建单据、新建巡检、录入结果、手动补录、商品/仓库新建、用户新建、资料和密码：

- 电脑：分组表单、实体选择器、实时摘要。
- 手机：按任务顺序排列，数字字段使用合适键盘，提交区固定但不遮挡内容。
- 批量标签操作在桌面用表格选择模式，在手机用显式选择模式。
- 连续扫码录入不得触发 Shell 全局跳转。

## 共用组件

- `ResponsiveDataView`：同一数据和列定义，桌面输出表格，手机输出业务卡片。
- `MasterDetailWorkspace`：桌面侧栏详情，手机压栈详情。
- `ShellAwareActionDock`：替代全屏 fixed 的 `BottomActionBar`。
- `FilterBar` 与 `PaginationBar`：统一筛选、结果范围和分页语义。
- `MetricGrid`：仅渲染真实 KPI，不产生趋势和预测。
- `KeyValuePanel` 与 `OperationTimeline`：详情字段和真实日志。
- `AsyncEntityPicker`：仓库、设备、计划等实体选择及四态。
- `ConfirmActionDialog`：初始焦点、焦点圈闭、Esc、关闭后恢复焦点和提交中禁用。
- `ScanEntry`：统一相机、扫码枪和手输入口。
- `useBridgeState`：以订阅方式呈现 Bridge 状态，避免读取一次性 getter。

## Bridge 重构

### 第一阶段修复

1. 桌面 Bridge 重启时为每次握手生成 generation，原子更新 bootstrap；页面在重连前重新读取 bootstrap，或在宿主确认新桥就绪后安全重载。
2. 重启计数只有在稳定运行窗口结束后才清零，阻止“握手后立即崩溃”的无限循环。
3. Android 用解析后的 URI 精确比较 scheme、host 和 port；相机只向壳来源授权视频资源。
4. 路径参数按单个 URL segment 编码；生产后端强制 HTTPS。
5. 帧按 UTF-8 字节限制，双向验证协议版本和结构，限制响应大小、连接数和并发请求。
6. 传输关闭能取消退避和 pending；会话刷新使用 single-flight，二次鉴权失败广播过期。
7. 修复 Android API 25 不兼容的 `File.toPath()`。

### 类型与模块边界

- `bridge:protocol` 只保留 wire frame、bootstrap 和协议常量。
- HTTP 路由及域契约迁往独立 contract 模块。
- 无 Netty/OkHttp 的 core 承担 dispatcher、session、端口和共享调用语义。
- OkHttp adapter 只承担 URL、信封与后端 I/O。
- credentials 模块承担 token pair、持久化和 secret codec；宿主保留 DPAPI/Keystore adapter。
- Web 侧由生成契约产生 method → params/result 类型映射，并为入站帧增加运行时校验。
- TransportPort 成为真实接口，Netty 与 Plain 使用同一套一致性测试。

### 高置信度废弃代码

必须先让结构门禁失败，再删除以下零引用且无兼容职责的表面：

- `BridgeDispatcher.allowedMethodIds`、`invalidParams`、`unreachable`；
- `SessionManager.sessionExpired`；
- `BridgeCallHandler.pongPayload()`；
- 未使用的 `BridgeServer` / `PlainWebSocketServer` port 与 connection count getter；
- `PersistentTokenStore.envelopeOf()`；
- 未使用的后端错误码常量；
- 生成器输出中无消费者的 `BridgeContract.VERSION` 与 `of(domain)`；
- 热恢复完成后，无渲染端消费者的 Electron `bridge-state` IPC；
- 经构建验证后，多余的 Kotlin compiler plugin 和项目依赖。

以下内容明确保留：

- Plain WebSocket transport、transport kind 和 loopback self-test；
- 现场诊断脚本；
- EventSink/EventSourcePort；
- PlatformPort、LocalMethodPort、MockTransport、能力 ID 和限频协议常量；
- 当前完整生成契约与隐藏方法；
- bootstrap、协议 v3、503 未就绪、会话事件和凭据格式。

## 错误与状态语义

- 会话状态区分 authenticated、unauthenticated、expired、offline 和 bridge failure；Bridge 故障不再伪装成登录页。
- `passwordChangeRequired` 必须进入强制改密门。
- 连接状态通过可订阅 store 更新，单个订阅者异常不阻断其他订阅者。
- 所有写操作在进行中禁止重复提交；失败保留用户输入并提供可重试动作。
- 大帧、版本不符、后端响应过大、并发过载和不支持的 wire mode 返回明确结构化错误。

## 测试策略

### 测试先行

每项行为变更先建立能稳定失败的测试，再实现最小修复：

1. 杀死桌面 JVM 后 bootstrap 更新且页面能再次 ping；
2. 连续握手后崩溃进入 failed，不无限重启；
3. Android 伪装 origin 和非壳相机请求被拒绝；
4. 路径保留字符只能形成一个编码后的 segment；
5. ASCII/CJK 在帧边界行为一致；
6. `close()` 后不再建 socket；
7. 并发 401 只刷新一次，重放再次 401 触发过期；
8. 动作槽不遮挡手机底栏和桌面侧栏；
9. 跨 600px 断点保留路由、筛选和未提交表单；
10. 连续扫码录入不发生全局跳转。

### 离线门禁

- TypeScript typecheck 和 Web build；
- CSS、UI、render、state、scan、stockorder、navigation、transport、timeout、session、refetch 检查；
- protocol、backend、capability、server 和 desktop host JVM 测试；
- fresh desktop bridge build 后再运行 benchmark。

日常门禁不调用会读取迁移归档的 legacy/parity 检查；迁移审计单独保留。

### 双端验收

- 视口：320、360、390、412、599、600、839、840、1024、1280、1440px。
- 页面：登录、四个域入口、所有列表、详情、长表单、四态和危险确认。
- UI：无横向溢出、无动作遮挡、主要触控目标不小于 48px、键盘焦点完整、严重无障碍问题为 0。
- 桌面：fresh build、Bridge 崩溃恢复、安装/启动/卸载。
- Android：API 25、API 34 和至少一台低端真机，覆盖登录、权限、IME、相机和扫码枪。

## 实施顺序与回滚

每个阶段保持独立提交边界，但不在本设计阶段提交代码：

1. Bridge 红测、P0 修复和纯删除；
2. 共享导航与动作槽；
3. tokens、patterns、可访问性和响应式数据组件；
4. 按“概览 → 库存 → 现场 → 我的”逐域迁移；
5. 桌面和 Android 发布门禁。

每次迁移一个域时保留原数据调用和 mutation 逻辑，仅替换呈现层。出现业务回归时可按域回滚 UI，不回滚已独立验证的 Bridge 安全修复。

## 完成标准

- 25 个现有视图都使用统一视觉语言，且没有凭空增加业务字段或动作。
- 电脑列表真正使用表格/主从布局，手机保持任务流和扫码优先。
- 动作区不遮挡内容、底栏或侧栏。
- 跨断点和宿主重连不丢失必要状态。
- Bridge P0 问题有自动化回归测试，高置信度废弃代码已删除。
- 离线门禁全绿；Android full lint 零错误；发布产物来自 fresh build。
